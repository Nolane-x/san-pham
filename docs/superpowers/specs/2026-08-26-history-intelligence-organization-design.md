# Magic Capture Desktop 4.14 — History Intelligence & Organization Design

## Goal
Turn History from a flat capture list into a local-first library that can be organized, filtered by how captures were used, and navigated efficiently without adding a daemon, database server, cloud dependency, or semantic-search claim that cannot be justified.

## Scope
This wave completes feature rows #258, #259, #260, #272, #273, #275, #280, #285, #286, #287, #451, and #454. Feature #289 local semantic search and #290 remain unchanged.

## Model
History organization is persisted separately from the image index in `history-library.json` so frequent organizational changes cannot corrupt the primary history index. The schema contains bounded workspace, folder, collection, membership, and per-asset activity records.

- Workspace: top-level context. A capture belongs to at most one workspace.
- Folder: one level below a workspace. A capture belongs to at most one folder and that folder must belong to the selected workspace.
- Collection: named many-to-many set. A capture may belong to multiple collections.
- Activity: bounded workflow IDs, AI-action IDs, open/use count, and last-used UTC.

All identifiers are opaque lowercase `Guid:N` strings generated by the app. User-visible names are normalized, bounded, case-insensitive for uniqueness within their scope, and never used as paths.

## Bounds
- 32 workspaces.
- 128 folders total, at most 64 per workspace.
- 128 collections.
- 5,000 membership links per collection.
- 32 collection memberships per capture.
- 32 workflow IDs and 32 AI-action IDs per capture.
- UseCount saturates at 1,000,000.
- Library JSON maximum 32 MiB.

## History query integration
`HistoryQueryOptions` gains optional WorkspaceId, FolderId, CollectionId, WorkflowId and AiActionId filters and a MostUsed sort order. The pure Core query accepts an optional library snapshot so query behavior remains deterministic and unit-testable.

## Activity tracking
Opening a History item increments usage. Running a workflow on a History capture records the workflow ID only after execution begins; a failed workflow is still activity because the capture was used. Running a Magic Action directly from a History-backed asset records the action ID through an optional history source identifier in the execution request/host path. Activity stores identifiers only, never prompt text, OCR text, model output, HTTP payloads, or image bytes.

## App/process metadata
Window capture resolves executable path best-effort with `Process.MainModule?.FileName` under exception guards. `CaptureAsset` and `HistoryItem` gain optional `ExecutablePath`. History import/rebuild leaves it null. A local icon cache derives a small PNG from executable icon when available and exposes it in `HistoryDisplayItem`; icon failures never fail capture/history operations.

## Drag/drop and timeline
History page becomes an `AllowDrop` target. Dropping supported image files imports them using the existing bounded image reader. Dropping folders enumerates only the top-level supported images by default, with a hard cap of 500 files per drop; no recursive filesystem crawl. Timeline mode groups the already-filtered History results by local calendar day and keeps selection/open behavior available.

## UI
Add a compact History organization bar with Workspace, Folder, Collection and View selectors plus Manage button. A management dialog creates/renames/deletes workspaces, folders and collections and assigns selected captures. Filters dialog gains Workflow and AI Action fields; sort gains MostUsed. Timeline/List view is explicit and persisted only for the current session.

Deleting an organizer object removes references only; it never deletes captures. Deleting a workspace also deletes its folder definitions and clears affected workspace/folder assignments, but collection memberships are preserved.

## Reliability and privacy
`history-library.json` uses `AtomicJsonFile`, `.bak` recovery, strict validation, and quarantine-on-invalid semantics matching other local configuration stores. History deletion prunes library membership/activity best-effort after primary image/index authority commits. A corrupt library never makes captures inaccessible; History falls back to an empty organizer snapshot and surfaces a warning/log.

## Release truth
Only the twelve scoped feature rows may change status in 4.14. The 4.13 audit is the comparison authority. Source release must remain deterministic and must run a dedicated `verify-history-intelligence.py` contract before packaging.
